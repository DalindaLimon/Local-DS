# Frontend

The whole UI is three files in [app/static/](../app/static), served as-is. **No npm, no bundler, no framework,
no build step.** Edit a file, reload the browser.

| File | Contents |
|---|---|
| [`index.html`](../app/static/index.html) | Page shell: meta tags, the `#view` container, the bottom tab bar, toast and sheet roots. Loads `app.css` and `app.js` with a `?v=` version query |
| [`app.js`](../app/static/app.js) | One ES module (~1500 lines) with every view, organized in sections |
| [`app.css`](../app/static/app.css) | All styles: design tokens, components, themes, layouts |
| [`sw.js`](../app/static/sw.js) | Service worker: caches the app shell only |
| [`manifest.webmanifest`](../app/static/manifest.webmanifest) | PWA name, icons, colors |
| `icons/` | App icons (generated by `scripts/make_icons.py`) |

## Building DOM with h()

Every element is created with `h(tag, attrs, ...children)`:

```js
const card = h('article', { class: 'card post', dataset: { id: item.id } },
  h('h2', {}, item.title),                               // strings become text nodes (safe)
  item.excerpt ? h('p', { class: 'excerpt' }, item.excerpt) : null,   // null/false children are skipped
  h('button', { type: 'button', onclick: () => like() }, icon('heart')));
```

- `class`, `dataset`, `style` (object) and `on<event>` functions are handled specially; `true` sets a boolean
  attribute; `null`/`false`/`undefined` skip the attribute.
- **Children that are strings become text nodes.** This is the XSS protection: feed titles, usernames, comments
  etc. are always inserted as text.
- `html: '...'` sets `innerHTML`. Use it **only** for trusted constants (the `ICONS`) or the server-sanitized
  `content_html` in the reader view. Never for user or feed text.

The strict Content-Security-Policy (`script-src 'self'`) forbids inline scripts and `onclick="..."` attributes in
HTML; always attach handlers in JS.

## Talking to the API

```js
const data = await api('/api/feed?mode=latest');                       // GET
const res = await api('/api/react', { method: 'POST', body: { type: 'item', id, value: 1 } });
```

`api()` sends cookies, adds the `X-CSRF-Token` header (from the `sf_csrf` cookie) on non-GET requests, encodes
`body` as JSON, and throws an `ApiError` with the server's `detail` message on failure. A 401 logs the user out of
the UI. Show errors with `toastErr(e)`.

**Seen tracking:** cards that scroll past the top go into `seenQueue`, which is flushed to `POST /api/seen` every
3 s and when the page is hidden.

## Routing and views

Hash-based routing (`#/feed`, `#/item/123`, …). `routes` maps a regex to a view function;
`render()` runs on every `hashchange`:

1. closes any open sheet and runs the previous view's `cleanupView()` (to remove listeners, observers, timers),
2. shows setup/login/register if needed,
3. calls `applyTheme(state.user)`,
4. calls the matching `view*(viewEl, ...params)`, which replaces `#view`'s content.

| Route | View | Notes |
|---|---|---|
| `#/feed` | `viewFeed` | DOM and scroll position are kept in `feedCache` when you open an item and come back |
| `#/item/:id` | `viewItem` | Reader view with comments |
| `#/reels` | `viewReels` | Full-screen; adds `body.reels-mode` |
| `#/past` | `viewPast` | Past Shorts |
| `#/sources`, `#/discover` | `viewSources`, `viewDiscover` | |
| `#/account`, `#/activity`, `#/admin` | `viewAccount`, `viewActivity`, `viewAdmin` | |
| `#/invite/:token` | `viewRegister` | Only when logged out |

A view function follows this pattern:

```js
function viewExample(view) {
  setTabs('menu');                                     // which bottom tab is highlighted
  const list = h('div', { class: 'list' });
  view.replaceChildren(
    h('header', { class: 'topbar' }, h('div', { class: 'topbar-row' }, h('h1', {}, 'Example'))),
    list);
  const timer = setInterval(() => {}, 5000);
  cleanupView = () => clearInterval(timer);            // runs when the user navigates away
  api('/api/something').then((d) => list.replaceChildren(...d.items.map(row))).catch(toastErr);
}
```

**Infinite lists** (feed, past, activity) use an `IntersectionObserver` on a sentinel element below the list, a
`cursor` from the API, and a `gen` counter so responses from an old filter are ignored after the filter changes.

**Reels** keeps one `<section class="slide">` per Short in a scroll-snap container. Only the current and next
slides have a video `src` (memory on phones). An IntersectionObserver decides the active slide, plays it muted,
and loads more when 3 are left.

## Shared UI pieces

| Helper | Use |
|---|---|
| `toast(msg, {action, onAction, error, ms})` | Small message above the tab bar, optional action button (e.g. *Undo*) |
| `openSheet({title, body, foot, tall, onClose})` | Bottom sheet (comments, composer, menu). Handles the iOS keyboard and drag-to-close |
| `reactionButtons(type, obj, {onDislike, onChange})` | Like/dislike pair with optimistic update and rollback on error |
| `commentThread(type, id)` / `openComments()` | Comment list + composer |
| `itemCard(item, ctx)` | A feed card (class `card post`) |
| `pastCard(short)` | A compact Short row |
| `skeletonCards(n)` | Loading placeholders |
| `icon(name)` | SVG from `ICONS` (add new icons there as path data) |
| `askButton(type, obj, cls)` / `openAsk(type, obj)` | Ask AI button (hidden unless `state.ai`) and its sheet. The answer is set with `textContent` (plain text, never HTML) |
| `priorityButton(type, obj, cls)` | Flag button that shows and changes `obj.priority` |

## CSS: tokens, themes, colors, layouts

`app.css` starts with **design tokens** on `:root`: colors (`--bg`, `--bg-2`, `--card`, `--card-2`, `--line`,
`--text`, `--muted`, `--faint`, `--accent`, `--accent-ink`, `--like`, `--dislike`, `--ok`, `--warn`, `--err`),
`--radius`, `--tabbar-h`, safe-area insets (`--safe-t/b/l/r`), `--col` (max content width, 640 px) and `--font`.
**Always use the tokens** instead of hard-coded colors so themes keep working.

`applyTheme()` sets three attributes on `<html>`, from the user's saved prefs (and caches them in localStorage
so the login page and the next start look the same):

| Attribute | Values | CSS |
|---|---|---|
| `data-theme` | `system`, `dark`, `black`, `light` | Dark tokens are the default. Light tokens apply under `@media (prefers-color-scheme: light)` unless the theme is `dark`/`black`, and always for `[data-theme="light"]`. `[data-theme="black"]` overrides the backgrounds with pure black |
| `data-accent` | `ember`, `ocean`, `forest`, `grape`, `rose`, `gold` | `:root[data-accent="ocean"] { --accent: … }`. Gold also sets a dark `--accent-ink` for contrast |
| `data-layout` | `cards`, `compact`, `magazine` | Rules under `/* feed layouts */` restyle `.card.post` (CSS grid for compact; image-first, full-bleed for magazine) |

**Add a color:** add a `:root[data-accent="name"]` rule and a `.swatch[data-accent="name"]` rule in `app.css`,
add `['name', 'Label']` to `ACCENTS` in `app.js`, and add `"name"` to the `accent` `Literal` in `Prefs`
([app/api_auth.py](../app/api_auth.py)). No database change: the column is plain text.

**Add a layout:** same idea with `LAYOUTS`, the `layout` `Literal`, CSS rules for
`:root[data-layout="name"] .card.post …`, and a small preview style for `.layout-pick[data-layout="name"]`.

## Mobile rules

These are checked by `scripts/screenshots.py` at 360/390/430 px:

- Use `100dvh` (not `100vh`) and the safe-area variables for anything at the screen edges.
- Inputs at least **16 px** font size (otherwise iOS zooms in on focus).
- Tap targets at least **44 px**.
- **No horizontal scroll** at 360 px.
- Reels: `scroll-snap-type: y mandatory`, `playsinline`, `muted` autoplay, only current + next video get a `src`.

## PWA and the service worker

[`sw.js`](../app/static/sw.js) caches only the **app shell** (`/`, `app.css`, `app.js`, icons, manifest) under a
cache named by `VERSION`:

- `/` and navigations: **network first**, cached copy when offline.
- `/static/*` and the manifest: **cache first**.
- `/api/*`, `/media/*`, `/healthz`: never cached.
- On activate, caches with another `VERSION` are deleted.

`/sw.js` is served from the site root (so it controls the whole site) with `Cache-Control: no-cache`.

## Shipping frontend changes

Because `app.css` and `app.js` are cache-first, **phones keep the old files until the version changes.** Whenever
you change anything in `app/static/`, bump all of these to the same new value:

1. `?v=` on `app.css` and `app.js` in [`index.html`](../app/static/index.html),
2. the same `?v=` in the `SHELL` list in [`sw.js`](../app/static/sw.js),
3. `VERSION` in `sw.js` (e.g. `localds-shell-0.3.1`).

Usually that's the app version from `app/__init__.py`. Then check syntax with
`node --check app/static/app.js && node --check app/static/sw.js`.

While developing in a desktop browser, DevTools → Application → Service Workers → *Update on reload* (or
*Unregister*) avoids stale files.
